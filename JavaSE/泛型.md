# 泛型

所谓泛型，其实就是C++中的模板，通过模板将一个个具体的类型进行泛化。

在成绩输入过程中，可能为`优秀`，也可能为`98.5`，两种结果，那么我们需要定义一个Score类：

```java
public class Score{
    String name;
    String id;
    Object value;//因为Object是所有类型的父类，那么可以用Object来定义
    
    public Score(String name,String id,Object value){
        this.name=name;
        this.id=id;
        this.value=value;
    }
}
```

使用Object进行编译时，我们需要进行强制类型转换，虽然可以，但却不是最好的方案，因此引入类泛型。

## 泛型类

我们可以这样定义：

```java
public class Score<T>{
    String name;
    String id;
    T value;  //T可以根据使用场景进行自动转换
    public Score(String name,String id,T value){  //T一旦确定，不能改变
        this.name=name;
        this.id=id;
        this.value=value;
    }
}
```

```java
public static void main(String[] args){
    Score<String>s=new Score<String>("计算机网络", "EP074512", "优秀");
    //<>内写入需要的类型
    String v=score.value;//一旦确定类型，那么泛型就变成了明确的类型
    System.out.println(v);
}
```

泛型将具体类型的判断放到了编译阶段，在编写代码的阶段就需要确定类型。

而在静态方法中，由于静态方法的调用是直接使用类名而不是将类实例化，因此跳过了泛型确定类型的节点，**因此在静态方法中是无法使用泛型的**。

只不过需要注意一下，在方法中还没有确定泛型的类型时，默认的变量会是一个Object的；

同理，不能使用还未确定的类型来直接实例化对象和数组。

### 通配符

通配符`?`允许我们在不知道具体类型的情况下来处理泛型对象

```java
public static void main(String[] args){
    Test<?>t=new Test<Integer>();
    t=new Test<String>();
    Object o=test.value;  //但需要注意，使用通配符证明类型还不确定，具体类型仍然是Object的子类
}
```

当然泛型也可以定义多个：

```java
public class Test<A, B, C> {   //多个类型变量使用逗号隔开
    public A a;
    public B b;
    public C c;
}
```

那么在使用时，这三种类型都得明确指定：

```java
public static void main(String[] args){
    Test<String,Integer,Character>t=new Test<>();//后面的可以省略
    t.a="lbwnb";
    t.b=666;
    t.c='娣?;
}
```

只要是在类中，那么都可以使用泛型变量：

```java
public class Test<T>{
    private T value;
    public void setValue<T value>{
        this.value=value;
    }
    public T getValue{
        return value;
    }
}
```

奥对了，泛型只支持引用类型，不支持基本类型（int，double）等等，存放基本类型的值，使用它对应的包装类（Integer,Double)等等。

当然，如果数组中存放的是基本类型，这个可以，因为数组本身是引用类型：

```java
public static void main(String[] args){
    Test<int[]>t=new Test<>();
}
```

## 泛型和多态

不只是类，接口和抽象类同样是支持泛型的：

```java
public interface Study<T>{
    T test();
}
```

当子类实现接口时，我们可以在子类将泛型实现：

```java
public class Main{
    public static void main(String[] args){
        A a=new A();
        Integer i=a.test();
    }
    static class A implements Study<Integer>{
        @Override
        public Integer test(){
            return null;
        }
    }
}
```

当然，也可以继续摆烂，依旧使用泛型：

```java
public class Main{
    public static void main(String[] args){
        A a=new A();
        Integer i=a.test();
    }
    static class A<T> implements Study<T>{
         @Override
        public T test() {
            return null;
        }
    }
}
    
```

继承同理：

```java
static class A<T>{
    
}
static class B extends A<String>{
    
}
```

## 泛型方法

同理，我们也可以定义泛型方法，无论是静态方法和成员方法需要接受的类型不确定时，我们可以用泛型来表示：

```java
public class Main{
    public static void main(String[] args){
    String str=test("Hello World");
    }
    private static<T>T test(T t){
        return t;
    }
}
```

泛型方法会在使用时自动确定泛型类型，比如上我们定义的是类型T作为参数，同样的类型T作为返回值，实际传入的参数是一个字符串类型的值，那么T就会自动变成String类型，因此返回值也是String类型。

事实上，泛型方法在许多工具类中都有使用，比如说Arrays的排序方法：

```java
Integer[] arr= {1, 4, 5, 2, 6, 3, 0, 7, 9, 8};
Arrays.sort(arr,Comparator<Integer>(){
   //通过创建泛型接口的匿名内部类，来自定义排序接口，因为匿名内部类就是接口的实现类，所以说这里明确了类型。
    @Overrride
    public int compare(Integer o1,Integer o2){
        return 0;
    }
});
```

比如这里，我们向从大到小排列：

```java
public static void main(String[] args){
    Integer[] arr= {1, 4, 5, 2, 6, 3, 0, 7, 9, 8};
    Arrays.sort(arr,Comparator<Integer>(){
        @Override
        public int compare(Integer o1,Integer o2){
            return o2-o1;
            //如果o2比o1大，那么肯定排在前面，所以说返回正数表示大于
        }
    });
    System.out.println(Arrays.toString(arr));
}
```

然后用Lambda表达式来表示：

```java
public static void main(String[] args) {
    Integer[] arr = {1, 4, 5, 2, 6, 3, 0, 7, 9, 8};
    Arrays.sort(arr, (o1, o2) -> o2 - o1);   //瞬间变一行，效果跟上面是一样的
    System.out.printljavan(Arrays.toString(arr));
}
```

包括数组的复制方法：

```java
public static void main(String[] args) {
    String[] arr = {"AAA", "BBB", "CCC"};
    String[] newArr = Arrays.copyOf(arr, 3);   //这里传入的类型是什么，返回的类型就是什么，也是用到了泛型
    System.out.println(Arrays.toString(newArr));
}
```

## 泛型的界限

现在增加一个新的要求，要求没有String类型，只要求要整型，并且必须要指定，这时我们可以定义泛型的界限来处理这个问题：

```java
public class Score<T extends Number>{  //设定上界，要求T必须是Number类或者Number的子类
    String name;
    String id;
    T value;
    
    public Score(String name,String id,T value){
        this.name=name;
        this.id=id;
        this.value=value;
    }
    
    public T getValue(){
        return value;
    }
}
```

同时，泛型通配符同样支持范围的限定：

```java
public static void main(String[] args){
    Score<? extends Integer> s=new Score<>("数据结构与算法", "EP074512", 60);
}
```

同样，既有上界，也有下界，下界的符号是`super`。

当限定了上界以后，那么使用该对象的泛型变量成员时，不再默认为Object类，而是对应的上界类；但对于下界而言却还是Object。

## 类型擦除

事实上，并不是真的有泛型这个东西，这个属于人为规定的，在泛型进行编译之后，所有的泛型会变成默认类型：

编译之前：

```java
public abstract class A<T>{
    abstract T test(T t); 
}
```

编译之后：

```java
public abstract class A{
    abstract Object test(Object t);
}
```

当然，如果我们给泛型设定了上界，那么默认会成为上界的类型：

编译之前：

```java
public abstract class A<T extends Number>{
    abstract T test(T t); 
}
```

编译之后：

```java
public abstract class A{
    abstract Number test(Number t); 
}
```

因此，泛型其实是在编译时进行类型检查，而在运行时，是不会真的检查对应的类型，所以说哪怕我们不去指定类型也可以直接使用：

```java
public static void main(String[] args) {
    Test test = new Test();    //对于泛型类Test，不指定具体类型也是可以的，默认就是原始类型
}
```

只不过编译会发出警告，[image-20220927131226728](https://oss.itbaima.cn/internal/markdown/2022/09/27/kVCIg3TilOuLFmj.png)

同样的，因为类型擦除，我们在使用时，编译后代码是做了强制转换的：

编译之前：

```java
public static void main(String[] args){
    A<String> a=new B();
    String i=a.test("10");
}
```

编译之后：

```java
public static void main(String[] args){
    A a=new B();
    String i=(String)a.test("10");
}
```

注意，这里要思考一个问题，既然继承泛型类之后要明确具体的类型，那么为什么重写不会发生错误呢，在重写的章节中我们说过，重写其实是对父类的方法进行重写，要求类型和形参保持一致，但继承泛型类后具体类型可能不一样，为什么没有报错。

```java
public abstract class A<T>{
    abstract T test(T t); 
}

public class B extends A<String>{
    @Override
    String test(String s){
        return null;
    }
}
```

在A类中，我们的方法实际上是Object，但在重写之后改成了String，但显然没有报错这是为何：

编译之后，我们通过反编译进行观察：

```java
// Compiled from "B.java"
public class com.test.entity.B extends com.test.entity.A<java.lang.String> {
  public com.test.entity.B();
  java.lang.String test(java.lang.String);
  java.lang.Object test(java.lang.Object);   //桥接方法，这才是真正重写的方法，但是使用时会调用上面的方法
}
```

通过反编译进行观察，实际上是编译器帮助我们生成了一个桥接方法用于支持重写：                       

```java
public class B extends A {
    
    public Object test(Object obj) {   //这才是重写的桥接方法
        return this.test((Integer) obj);   //桥接方法调用我们自己写的方法
    }
    
    public String test(String str) {   //我们自己写的方法
        return null;
    }
}
```

类型擦除机制其实是为了方便后面使用集合类（不然每次都要强制转换）同时为了向下兼容采取的方案：因此，泛型的使用会有一些限制：

首先，在进行类型判断时，不允许使用泛型，只能使用原始类型：

![image-20220927133232627](https://oss.itbaima.cn/internal/markdown/2022/09/27/q7DQ9lAweJLOFky.png)

只能判断是不是原始类型，里面的具体类型是不支持的：

```java
Test<String> test = new Test<>();
System.out.println(test instanceof Test);   //在进行类型判断时，不允许使用泛型，只能使用原始类型
```

还有，泛型类型是不支持创建参数化类型数组的：

![image-20220927133611288](https://oss.itbaima.cn/internal/markdown/2022/09/27/7tK5APuSZovBLIc.png)

要用只能用原始类型：

```java
public static void main(String[] args) {
    Test[] test = new Test[10];   //同样是因为类型擦除导致的，运行时可不会去检查具体类型是什么
}
```

## 函数式接口

本小结的内容先学习，后续道明为什么这么使用。

这些函数式接口都可以使用Lambda表达式，非常方便，这里需要介绍四种：

### Supplier供给型函数式接口：

这个接口是专门用于供给使用的，其中只有一个get方法用于获取需要的对象。

```java
//以下代码是源代码，不用自己写
@FunctionalInterface  //函数式接口都会打上这样一个注解
public interface Supplier<T>{
    T get();  //实现此方法，实现供给功能
}
```

比如我们要专门实现一个专门供给Student对象的Supplier，就可以这样使用：

```java
public static class Student{
    public void Hello(){
        System.out.println("我是学生");
    }
}
```

```java
public static void main(String[] args){
    Supplier<Student> ss=new Supplier<Student>(){
        @Override
        public Student get(){
            return new Student();
        };
        ss.get().Hello();
    }
}
```

将他简写：（原函数->Lambda表达式->方法引用）

```java
//专门供给Student对象的Supplier
private static final Supplier<Student> ss = Student::new;
public static void main(String[] args) {
    Student s = ss.get();
    s.hello();
}
```

### Consumer消费型接口：

这个接口是专门用于消费某个对象的。

```java
//以下代码是源代码，不用自己写
@FunctionalInterface
public interface Consumer<T> {
    void accept(T t);    //这个方法就是用于消费的，没有返回值

    default Consumer<T> andThen(Consumer<? super T> after) {   //这个方法便于我们连续使用此消费接口
        Objects.requireNonNull(after);
        return (T t) -> { accept(t); after.accept(t); };
    }
}
```

以下是使用方法：

```java
private static final Consumer<Student> cs=s->System.out.println(s+"真好吃！");
public static void main(String[] args){
    Student s=new Student();
    cs.accept(s);
}
```

可以使用`andThen`继续调用：

```java
    private static final Consumer<Student> cs=student->System.out.println(student+" 真好吃！");
    public static void main(String[] args) {
        Student student = new Student();
              cs   //我们可以提前将消费之后的操作以同样的方式预定好
                .andThen(stu -> System.out.println("我是吃完之后的操作！"))
                .andThen(stu -> System.out.println("好了好了，吃饱了，"))
                .accept(student);   //预定好之后，再执行
    }
```

### Function函数型函数式接口：

这个接口会消费一个对象，向外供给一个对象（前两个函数式接口的集合体）。

```java
//以下是源代码，不用自己写
@FunctionalInterface
public interface Function<T, R> {
    R apply(T t);   //这里一共有两个类型参数，其中一个是接受的参数类型，还有一个是返回的结果类型

    default <V> Function<V, R> compose(Function<? super V, ? extends T> before) {
        Objects.requireNonNull(before);
        return (V v) -> apply(before.apply(v));
    }

    default <V> Function<T, V> andThen(Function<? super R, ? extends V> after) {
        Objects.requireNonNull(after);
        return (T t) -> after.apply(apply(t));
    }

    static <T> Function<T, T> identity() {
        return t -> t;
    }
}
```

#### apply用法

```java
//这里实现一个简单的功能，将int参数转换为String类型
private static final Function<Integer,String> fis=Object::toString;
public static void main(String[] args){
    String str=fis.apply(10);
    System.out.println(str);
}
```

#### compose用法

```java
private static final Function<Integer,String>fis=Object::toString;
public static void main(String[] args){
    String str=fis.compose((String s)->s.length()).apply("lbwnb");
    System.out.println(str);
}
```

compose用法是在调用apply之前加入一道用法，比如这里的str，实际上是先从传入的String类型进行compose里面的处理，即转换为5（length()），然后执行apply，转换为字符串。

#### andThen用法

```java
private static final Function<Integer,String>fis=Object::toString;
public static void main(String[] args){
    boolean str=fis.andThen(String::isEmpty).apply(10);
    System.out.println(str);
}
```

先进行apply用法，然后再将结果执行andThen用法。

#### identify用法

```java
public static void main(String[] args){
    Function<String,String>f=Function.identify();
    System.out.println(f.apply("怎么进去怎么出来"));
}
```

identify的意思就是怎么进去的，怎么出来。

### Predicate函数型函数式接口:

接收一个参数，进行自定义类型的判断并返回一个boolean结果。

```java
//以下是源代码，不用自己写
@FunctionalInterface
public interface Predicate<T> {
    boolean test(T t);    //这个方法就是我们要实现的

    default Predicate<T> and(Predicate<? super T> other) {
        Objects.requireNonNull(other);
        return (t) -> test(t) && other.test(t);
    }

    default Predicate<T> negate() {
        return (t) -> !test(t);
    }

    default Predicate<T> or(Predicate<? super T> other) {
        Objects.requireNonNull(other);
        return (t) -> test(t) || other.test(t);
    }

    static <T> Predicate<T> isEqual(Object targetRef) {
        return (null == targetRef)
                ? Objects::isNull
                : object -> targetRef.equals(object);
    }
}
```

首先，先简单编写一个例子：

```java
public class Student{
    public int Score;
}
```

```java
private static final Predicate<Student>ps=s->s.score>=60; 
public static void main(String[] args){
    Student ss=new Student();
    ss.score=80;
    if(ps.test(student)){  //返回一个布尔类型的结果
        System.out.println("Yes");
    }else{
        System.out.println("No");
    }
}
```

我们也可以组合条件来判断：

```java
private static final Predicate<Student>ps=s->s.score>=60; 
public static void main(String[] args){
    Student ss=new Student();
    ss.score=80;
    boolean b=ps.and(stu->stu.score>=90).test(student);//需要同时满足两个条件
```

同样的，这个类型提供了一个对应的实现，用于判断两个对象是否相等：              

```java
public static void main(String[] args) {
    Predicate<String> predicate = Predicate.isEqual("Hello World");   //这里传入的对象会和之后的进行比较
    System.out.println(predicate.test("Hello World"));
}
```

## 判空包装

java8还有一个非常重要的判空包装类Optional，这个类可以很高效的处理空指针的问题。

```java
private static void test(String str){   //传入字符串，如果不是空串，那么就打印长度
    if(!str.isEmpty()) {
        System.out.println("字符串长度为，" +str.length());
    }
}
```

如果这里放进去一个null，那么会发生错误。

如果按照以往的经验，那么会这样操作：

```java
private static void test(String str){
    if(str == null) return;   //这样就可以防止null导致的异常了
    if(!str.isEmpty()) {
        System.out.println("字符串长度为，" +str.length());
    }
}
```

此时，Optional为我们提供了一种新的用法：

```java
private static void test(String str){
    Optional
            .ofNullable(str)   //将传入的对象包装进Optional对象
            .ifPresent(s -> System.out.println("字符串长度为，" +s.length()));  
  					//如果不为空，则执行这里的Consumer实现
}
```

如果发生为空的情况，我们同样可以使用它来抛出异常：

```java
private static void test(String str){
    String s = Optional.ofNullable(str).get();   //get方法可以获取被包装的对象引用，但是如果为空的话，会抛出异常
    System.out.println(s);
}
```

我们可以对于这种有可能为空的情况进行处理，如果为空，那么就返回另一个备选方案：                    

```java
private static void test(String str){
    String s = Optional.ofNullable(str).orElse("我是为null的情况备选方案");
    System.out.println(s);
}
```

是不是感觉很方便？我们还可以将包装的类型直接转换为另一种类型：

```java
private static void test(String str){
    Integer i = Optional
            .ofNullable(str)
            .map(String::length) 
        //使用map来进行映射，将当前类型转换为其他类型，或者是进行处理
        //由于map还没有学，这里只做了解
            .orElse(-1);
    System.out.println(i);
}
```

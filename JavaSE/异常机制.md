# 异常

今天，我们来学习异常的分类和处理，顾名思义，异常其实就是程序运行时发生的错误，人毕竟不是计算机，总会有犯错的时候，了解异常的机制会让我们更好的对代码进行修正。

## 异常的类型

异常本质上其实也是一个类，他们都属于`Exception`类，只不过他们支持在程序运行出现问题时抛出，当然，也可以提前声明，告知使用者哪些是需要提前处理的异常。

### 运行时异常

异常的第一种类型是运行时异常，这类异常通常在编译时不会报错，往往是在运行时才知道错误在哪，他们是由类定义的，继承自`RuntimeException`类。

```java
public static void main(String[] args){
    Object obj=null;
    obj.toString();  //这种情况下会出现运行时异常
}
```

又比如以下这种情况：

```java
public static void main(String[] args){
    Object obj=new Object();
    Main m=(Main)obj;
}
```

### 编译时异常

异常的另一种类型是编译时异常，也就是在编译阶段会发现问题的异常，如果不对异常进行处理（捕获），那么程序将无法通过编译；默认继承`Exception`类的异常都是编译时异常。

比如`clone`，就明确指出在运行的时候会出现错误的异常。

```java
protected native Object clone() throws CloneNotSupportedException;
```

### 错误（这个不是异常，这章对于错误只做了解）

错误比异常更加严重，异常是那种不同寻常但不会产生致命的问题；而错误就是致命问题，一但发生错误，有可能JVM就无法继续正常运行了。

比如`OutOfMemoryError`就是内存溢出错误。

```java
public static void main(String[] args){
    test();
}
public static void test(){
    test();
}
```

就比如这样一个无限递归的方法，会造成栈溢出。[image-20220924165500108](https://oss.itbaima.cn/internal/markdown/2022/09/24/9YEZV2L73ROQTuA.png)

这种情况下就是错误了，已经严重到程序无法运行了。

又比如：

```java
public static void main(String[] args){
    Object obj=new Object(Integer.MAX_VALUE);//这里申请了一个超级大的数字
}
```

实际上我们的电脑是有限的，不可能无限制的使用内存来存放变量，因此会导致这样的问题，[image-20220924165657392](https://oss.itbaima.cn/internal/markdown/2022/09/24/qj8zJnGxdS5IybX.png)

## 自定义异常

##### 编译时异常

编译时异常只需要继承`Exception`就行了，编译时异常的子类有很多，光是JavaSE就有700多种；异常多种多样，不同的异常对应不同的情况，比如在类型转换时出错那么就是类型转换异常，如果是使用一个值为null的变量调用方法，那么就会出现空指针异常。

##### 运行时异常

运行时异常只需要继承一个`RuntimeException`就行了。

RuntimeException继承自Exception，Exception继承自Throwable：

![image-20220924203130042](https://oss.itbaima.cn/internal/markdown/2022/09/24/RjzWnNDc6TZeSoJ.png)

##### 错误

当然还有一种`Error`,它是所有错误的父类，同样继承于`Throwable`。

## 抛出异常

当别人调用了我们的方法时，如果传入了一个错误的参数，导致程序发生错误时，我们可以手动抛出一个异常来终止程序异常，并告知上一级方法执行出现了问题：

```java
public static int test(int a,int b){
    if(b==0){
        throw new RuntimeExpection("被除数不能为0");//使用throw关键字来抛出异常
    }
    return a/b;
}
```

![image-20220924200817314](https://oss.itbaima.cn/internal/markdown/2022/09/24/Ttr4kZSyodKi3M8.png)

抛出异常就需要创建一个对象出来，本质上还是异常对象的抛出，异常对象携带了我们抛出异常的一些信息，可以在方法中写明原因。

注意：如果不同分支都会出现不同的异常，我们都需要对抛出的异常进行注明：

```java
private static void test(int a) throws FileNotFoundException,ClassNotFoundExpection{
    if(a==0){
        throw new FileNotFountException();
    }else{
        throw new ClassNotFoundException();
    }
}
```

当然，并不是只有非运行时异常才可以明确指出，运行时异常也可以，只不过不强制要求：

```java
private static void test(int a)throws RuntimeException{
    throw new RuntimeException();
}
```

最后，如果父类的方法中表明了需要抛出异常，在重写方法时，只要重写的内容中不需要抛出对应的异常，我们就可以直接省略。

## 异常的处理

当程序没有按照我们理想的样子进行运行而出现异常时（默认会交给JVM来处理，而JVM在发现异常时会阻止程序运行，并让控制台打印异常信息），现在我们希望自己处理异常，让程序能够进行下去，我们需要对异常进行捕获，比如：

```java
public static void main(String[] args){
    try{ //使用try-catch来捕获异常
        Obiect obj=null;
        obj.toString();
    }catch(NullPointerException e){      
    } //因为异常本身就是一个对象，那么catch实际上是让一个局部变量来接收异常
        System.out.println("程序正常运行");
}
```

我们将代码编辑到了try的代码块中，只要是这个区域内发生的异常，都可以被catch捕获，以此使得代码正常运行。

注意：catch捕获的只能是Throwable的子类，也就是说要么是抛出的异常，要么是错误，不能是其他类型。

我们可以在catch的代码块中对捕获的异常进行处理：

```java
public static void main(String[] args) {
    try {
        Object object = null;
        object.toString();
    } catch (NullPointerException e){
        e.printStackTrace();   //打印栈追踪信息
        System.out.println("异常错误信息，" + e.getMessage());   //获取异常的错误信息
    }
    System.out.println("程序继续正常运行，");
}
```

当然，如果我们不想当前这个方法内处理，我们可以踢皮球，让上一个方法进行处理。

```java
public static void main(String[] args) throws IOException{
    test(10);
}
public static void test(int a) throws IOException{
    throw new IOException();
}
```

注意：如果已经是主函数了，如果再往上一级抛出，那么结果就是给到了JVM进行处理，默认会让程序终止并打印栈追踪信息。

注意：如果我们要捕获异常时，是一个父类异常，当它的子类异常出现时，我们同样可以将其捕获。

```java
public static void main(String[] args) throws IOException{
    try{
        int[] arr=new int[1];
        arr[1]=100;//发生了数组越界，它是运行时异常的子类
    }catch(RuntimeException e){
        System.out.println("捕获到异常");
    }//这里运行时异常同样能够捕获到
}
```

当代码可能出现多种类型的异常时，我们希望能够分不同情况处理不同类型的异常，就可以使用多重异常捕获：           

```java
try {
  //....
} catch (NullPointerException e) {
            
} catch (IndexOutOfBoundsException e){

} catch (RuntimeException e){
            
}
```

但是要注意一下顺序：                 

```java
try {
  //....
} catch (RuntimeException e){  //父类型在前，会将子类的也捕获

} catch (NullPointerException e) {   //永远都不会被捕获

} catch (IndexOutOfBoundsException e){   //永远都不会被捕获

}
```

只不过这样写好像有点丑，我们也可以简写为：          

```java
try {
     //....
} catch (NullPointerException | IndexOutOfBoundsException e) {  //用|隔开每种类型即可
		
}
```

如果简写的话，那么发生这些异常的时候，都会采用统一的方式进行处理了。

最后，当我们希望，程序无论出现异常，都会在最后执行任务，可以交给`final`来处理：

```java
try{
    
}catch(Exception e){
    
}final{
    System.out.println("hhh");//无论是否出现异常，都会在最后执行
}
```

`try`语句块至少要配合`catch`或`finally`中的一个：

```java
try {
    int a = 10;
    a /= 0;
} finally {  //不捕获异常，程序会终止，但在最后依然会执行下面的内容
    System.out.println("lbwnb"); 
}
```

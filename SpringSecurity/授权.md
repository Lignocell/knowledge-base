# 授权

用户登录后，可能会根据用户的身份来角色划分，就相当于一个QQ群，有群主，有管理员，有成员，群主具有最高权限，有解散群和升级群的资格，管理员有一部分，成员只有最基本的聊天操作。

对于我们来说，用户的一个操作实际上是在访问我们的接口（编写了对应路径的Servlet），比如登录，就需要调用 login接口，退出登录需要调用logout接口。因此，从我们开发者的角度来说，决定用户是否使用某个功能，只需要决定用户是否能够访问对应的Servlet即可。

我们可以按照以下进行划分：

- 群主：`/login`、`/logout`、`/chat`、`/edit`、`/delete`、`/upgrade`
- 管理员：`/login`、`/logout`、`/chat`、`/edit`
- 普通群成员：`/login`、`/logout`、`/chat`

也就是说，我们可以指定哪些请求可以由哪些用户发起。

SpringSecurity为我们提供了两种授权方式：

- 基于权限的授权：只要拥有某个权限的用户，就能访问某个路径。
- 基于角色的授权：根据用户属于哪个角色来决定是否可以访问哪个路径。

两者只是概念上有所不同，实际效果使用起来差不多。

## 基于角色授权

现在我们希望创建两个角色，普通用户和管理员，普通用户只能访问index页面，而管理员可以访问任何页面。

首先我们需要对数据库中的角色表进行一些修改，添加一个用户的角色字段，并创建一个新的用户，Test用户的角色为user，而Admin用户的角色为admin。

接着我们配置Security，决定哪些角色可以访问哪些页面：

```java
.authrizeHttpRequests(auth->{
    //静态资源依然可以全部访问
    auth.requestMatchers(new AntPathRequestMatcher("/static/**")).permitAll();
    //所有用户都可以访问路径/
    auth.requestMatchers("/").hasRole("user","admin");
    //其他路径只能由admin进行访问
    auth.anyRequest().hasRole("admin");
})
```

 接着，我们需要稍微修改一下验证逻辑，我们在数据库中的用户表上添加一个字段，用于表示角色，并修改实体类：

![image-20230704222733082](https://oss.itbaima.cn/internal/markdown/2023/07/04/1pkfGS9LrsPtjFx.png)

```java
@Data
public class Account {
    int id;
    String username;
    String password;
    String role;
}
```

现在我们在查询用户时，需要添加对应的角色：

```java
 @Override
public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
    Account account = mapper.findUserByName(username);
    if(account == null)
        throw new UsernameNotFoundException("用户名或密码错误");
    return User
            .withUsername(username)
            .password(account.getPassword())
            .roles(account.getRole())   //添加角色，一个用户可以有一个或多个角色
            .build();
}
```

这样就可以了，我们重启服务器登录看看：

![image-20230703182321093](https://oss.itbaima.cn/internal/markdown/2023/07/03/Zns4Vwb7zPLc6SQ.png)



目前依然是可以正常登录的，但是我们随便访问一个其他的页面，就会被拦截并自动退回到登录界面：

![image-20230704223248124](https://oss.itbaima.cn/internal/markdown/2023/07/04/8aoGrM9mpYt6Xie.png)



这是因为我们前面配置的是user角色，那么这个角色只能访问首页，其他的都不行，所以就会被自动拦截掉了。现在我们可以到数据库中对这个用户的角色进行修改，看看修改后是否能够访问到其他页面：

![image-20230704223503682](https://oss.itbaima.cn/internal/markdown/2023/07/04/l9YkDaRJdtrmSZj.png)



这样就可以访问其他页面不会被拦截了，不过因为我们没配置这个路径，所以出来的404页面。

通过使用角色控制页面的访问，我们就可以让某些用户只能访问部分页面。

## 基于权限授权

基于权限授权与角色类似，需要用hasAnyAuthority和hasAuthority来判断：

```java
.authorizeHttpRequests(auth -> {
    //静态资源依然全部可以访问
    auth.requestMatchers("/static/**").permitAll();
    //基于权限和基于角色其实差别并不大，使用方式是相同
    auth.anyRequest().hasAnyAuthority("page:index");
})
```

实际上权限跟角色相比只是粒度更细，由于使用方式差不多，这里不多做阐述。

## 使用注解权限判断

除了直接配置外，我们还可以以注解形式进行配置，首先需要在配置类上开启（注意这里是MVC的配置类，因为这里只针对Controller进行过滤，所有的Controller是由MVC配置类进行注册的，如果需要为Service或者其他Bean也启用权限判断，则需要在Security的配置类上添加）：

```java
@Configuration
@EnableWebSecurity
@EnableMethodSecurity  //开启方法安全校验
public class SecurityConfiguration{
    ...
}
```

现在我们就可以在我们想要进行权限校验的方法上添加注解了：

```java
@Controller
public class HelloController{
    @PreAuthorize("hasRole('user')")  //直接使用hasRole方法判断是否包含某个角色
    @GetMapping("/")
    public String index(){
        return "index";
    }
    ...
}
```

通过添加PreAuthorize注解，在执行前判断权限，如果没有对应的权限或者不是对应的角色，将无法访问此页面。

这里使用了SpingEL表达式，我们可以直接在这里使用权限判断的相关方法。所有可以进行权限判断的方法在SecurityExpressionRoot类中有定义，感兴趣的可以自行了解。

同样的还有@PostAuthorize注解，但是它是在方法之后进行拦截：

```java
@PostAuthorize("hasRole('user')")
@RequestMapping("/")
public String index(){
    System.out.println("执行");
    return "index";
}
```

除了Controller以外，只要是由Spring管理的Bean都可以使用注解的形式来控制权限，我们可以在任意方法上添加这个注解，只要不具备表达式上对应的权限，那么就无法执行该方法并返回403。

```java
@Service
public class UserService {

    @PreAuthorize("hasAnyRole('user')")
    public void test(){
        System.out.println("成功执行");
    }
}
```

我们还可以使用@PostFilter和@PreFilter对集合类型的参数或者返回值进行过滤：

```java
@PreFilter("filterObject.equals('lbwnb')")  //filterObject代表集合中的所有元素，只有满足条件的元素才会保留
public void test(List<String>list){
    System.out.println("成功执行"+list);
}
```

```java
@RequestMapping("/")
public String index(){
    List<String> list = new LinkedList<>();
    list.add("lbwnb");
    list.add("yyds");
    service.test(list);
    return "index";
}
```

@PostFilter类似，就不做演示了。

当有更多集合时，需要使用filterTarget进行指定：

```java
@PreFilter(value="filterObject.equals('lbwnb')",filterTarget="list2")
public void test(List<String>list,List<String>list2){
    System.out.println("成功执行"+list);
}
```

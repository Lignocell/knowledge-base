# 自定义登录界面与记住我

## 自定义登录界面

虽然，SpringSecurity为我们提供了一个还可以的登录界面，但是很多情况下我们还是自己定义登录界面，这种情况下，就需要我们自己进行配置了，我们随便找一个模板。

找到模板后，我们需要将资源放到类路径下，[image-20230703180438190](https://oss.itbaima.cn/internal/markdown/2023/07/03/hpZs1DLESojHJue.png)

接着，我们配置对应页面的Controller控制器：

```java
@Controller
public class HelloController{
    @GetMapping("/")
    public String index(){
        return "index";
    }
    @GetMapping("/login")
    public String login(){
        return "login";
    }
}
```

这样，我们在登录之后，就可以展示前端模版页面了：

![image-20230703182321093](https://oss.itbaima.cn/internal/markdown/2023/07/03/Zns4Vwb7zPLc6SQ.png)



不过现在依然是默认进入到SpringSecurity默认的登录界面，现在我们来配置自定义的登录界面，将我们的前端模版中的登录页面作为SpringSecurity的默认登录界面。

```java
@Configuraiton
@EnbaleWebSecurity
public class SecurityConfiguration{
    ...
        //如果你学习过SpringSecurity 5.X版本，可能会发现新版本的配置方式完全不一样
    //新版本全部采用lambda形式进行配置，无法再使用之前的and()方法进行连接
        @Bean
        public SecurityFilterChain filterChain(HttpSecurity http) throws Exception{
        return http
            //以下是验证请求拦截和放行的配置
            .authorizeHttpRequests(auth->{
                auth.anyRequest().authenticated();  //将请求全部拦截，一律需要验证
                //auth.anyRequest().permitAll();  所有请求全部放行
            })
            //以下是表单登录相关配置
            .formLogin(conf->{
                conf.loginPage("/login");  //将登录页设置为我们自己的
                conf.loginProcessingUrl("/doLogin");  //登录表单提交的地址（将账密提交到后端地址），可以自定义
                conf.defaultSuccessfulUrl("/");  //登陆成功后跳转的页面
                conf.permitAll();  //将登录相关的地址放行，否则未登录的用户来登录页面都进不去
                //用户名和密码的表单字段名称，不过默认就是这个，可以不配置，除非有特殊需求
                    conf.usernameParameter("username");
                    conf.passwordParameter("password");
            })
            .build();
    }
}
```

需要配置登录页面的网址和登录请求发送的地址，这里登录页填写/login，登录请求地址填写/doLogin，登陆页面我们刚刚已经编写Controller来实现了，登录请求提交处理由SpringSecurity来处理，只需要写对应的路径就可以了，现在我们来访问网站，就可以进入到自定义网站了：

![image-20230703184425313](https://oss.itbaima.cn/internal/markdown/2023/07/03/c38kewdxtn1j2V6.png)

但是我们发现，我们的页面只有纯文本，那是因为静态资源被拦截了，全部302重定向到登录界面了，这显然是错的：

![image-20230703184641792](https://oss.itbaima.cn/internal/markdown/2023/07/03/6vXlPZprzjJLEeq.png)

因此，我们现在要给所有的静态资源放行，否则登录页面没法展示：

```java
.authorizeHttpRequests(auth -> {
      auth.requestMatchers(new AntPathRequestMatcher("/static/**")).permitAll();   //将所有的静态资源放行，一定要添加在全部请求拦截之前
      auth.anyRequest().authenticated();    //将所有请求全部拦截，一律需要验证
})
```

再次访问，就可以正常看到了：

![image-20230703185027927](https://oss.itbaima.cn/internal/markdown/2023/07/03/LmZbihzD4vYB5GF.png)

因此，如果各位在编写项目时发现302情况时，一定要先检查一下是否是因为没被放行才导致的302情况。

接着我们来配置登录操作，这里我们只需要配置一下登录的地址和登录按钮即可，当然，跟之前一样，要把CSRF的输入框也加上：

```html
<form action="doLogin" method="post">
		...
  <input type="text" name="username" placeholder="Email Address" class="ad-input">
  ...
  <input type="password" name="password" placeholder="Password" class="ad-input">
  ...
  <input type="text" th:name="${_csrf.getParameterName()}" th:value="${_csrf.token}" hidden>
  <div class="ad-auth-btn">
     <button type="submit" class="ad-btn ad-login-member">Login</button>
  </div>
	...
</form>
```

接着我们就可以尝试进行登录操作了：

![image-20230703185916404](https://oss.itbaima.cn/internal/markdown/2023/07/03/P2LS8uNRQ64WEvT.png)



可以看到，现在我们可以成功地登录到主页了。

退出登录也是同样的操作，我们只需要稍微配置一下就可以实现，我们需要先完善一下配置类：

```java
@Configuration
@EnableWebSecurity
public class SecurityConfiguration{
    ...
        
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http)throws Exception{
        return http
            ...
            //以下是退出登录操作配置
            .logout(conf->{
                conf.logoutUrl("/doLogout");  //退出登录地址，与上面一样可以自定义
                conf.logoutSuccessUrl("/login");  //退出登录后跳转的地址，这里设置为登录界面
                conf.permitAll();
            })
            .build();
    }    
}
```

接下来，我们修改一下退出登录按钮：

```html
<li>
   <form action="doLogout" method="post">
        <input type="text" th:name="${_csrf.getParameterName()}" th:value="${_csrf.token}" hidden>
        <button type="submit">
           <i class="fas fa-sign-out-alt"></i> logout
        </button>
   </form>
</li>
```

现在我们可以正常进行退出操作了：

![image-20230703190714519](https://oss.itbaima.cn/internal/markdown/2023/07/03/yM8TOAxYPf3iqFs.png)

不过，可能会有人觉得什么都需要Csrf登录校验太麻烦了，浏览器的安全性已经足够高了，想要把校验关闭，我们可以在配置类中进行关闭：

```java
@Configuration
@EnableWebSecurity
public class SecurityConfiguration {

   	...
      
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http
                ...
                //以下是csrf相关配置
              .csrf(conf -> {
                    conf.disable();   //此方法可以直接关闭全部的csrf校验，一步到位
                    conf.ignoringRequestMatchers("/xxx/**");   //此方法可以根据情况忽略某些地址的csrf校验
                })
                .build();
    }
}           
```

这样，我们就不需要再往页面中嵌入CSRF相关的输入框了，发送请求时也不会进行校验，至此，我们就完成了简单的自定义登录界面配置。

## 记住我功能

网站登录界面还有一个主要的功能，那就是记住我，也就是在登陆后的一段时间内，如果我们退出会话，无需再次登录即可进入页面。

我们之前在JavaWeb的学习中实现过这一功能，但是使用了本地Cookie存储的方式，但是这种方式并不安全，那么我们需要实现一种更安全的方式。

SpringSecurity为我们提供了一种优秀的实现，它为每个已登录的浏览器分配了一个携带Token的Cookie，并且此Cookie会默认保存4天，只要我们不清理浏览器的Cookie，那么下次携带此Cookie访问服务器将无需登录，我们现在来配置一下实现此功能：

```java
@Configuration
@EnableWebSecurity
public class SecurityConfiguration {

    ...

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        return http
                ...
            .rememberMe(conf->{
                conf.alwaysRemember(false);  //这里不要开启始终记住，我们需要配置用户自己勾选
                conf.rememberMeParameter("remember-me");   //记住我表单字段，默认就是这个，可以不配置
                conf.rememberMeCookieName("xxxx");  //记住我设置的Cookie名字，也可以自定义，不过没必要
            })
            .build();
    }
}
```

配置完成后，我们需要修改一下前端页面的表单，将记住我勾选框作为表单的一部分进行提交：

```html
<div class="ad-checkbox">
    <label>
        <input type="checkbox" name="remember-me" class="ad-checkbox">
        <span>Remember Me</span>
    </label>
</div>
```

接着我们来尝试勾选记住我选项进行登录：

![image-20230704211415804](https://oss.itbaima.cn/internal/markdown/2023/07/04/3wOt7CldbFP8yHz.png)

此时提交的表单中就已经包含记住我字段了，我们会发现，服务端返回给我们了一个记住我专属的Cookie信息：

![image-20230704211611369](https://oss.itbaima.cn/internal/markdown/2023/07/04/NB129h7IKRycXvL.png)

这个Cookie信息的过期时间并不是仅会话，而是默认保存一段时间，因此，我们浏览器关闭后再次访问时就不需要重新进行登录了。

当然，现在记住我的信息是保存在内存中，我们需要保持服务器一致处于运行状态，但是如果我们关闭服务器的话，记住我的的信息就会全部丢失，我们需要重新找一个地方来保存，那么，我们想到了数据库。

我们需要创建一个基于JDBC的TokenRepository实现：

```java
@Bean
public PersistentTokenRepository tokenRepository(DataSource dataSource){
    JdbcTokenRepositoryImpl repository =new JdbcTokenRepositoryImply();
    //在启动时自动在数据库中创建存储记住我信息的表，仅第一次需要，后续不需要
    repository.setCreateTableOnStartup(true);
    repository.setDataSource(dataSource);
    return repository;
}
```

然后添加到仓库：

```java
.rememberMe(conf -> {
     conf.rememberMeParameter("remember-me");
     conf.tokenRepository(repository);      //设置刚刚的记住我持久化存储库
     conf.tokenValiditySeconds(3600 * 7);   //设置记住我有效时间为7天
})
```

这样，我们就成功配置了数据库持久化存储记住我信息，即使我们重启服务器也不会导致数据丢失。当我们登录之后，数据库中会自动记录相关的信息：

![image-20230704220701000](https://oss.itbaima.cn/internal/markdown/2023/07/04/kIJpuWdiEGqUKBx.png)



这样，我们网站的登录系统就更加完善了。

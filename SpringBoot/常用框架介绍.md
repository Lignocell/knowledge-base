前面我们介绍了SpringBoot项目的基本搭建，但是光靠这些还是不够，我们还需要了解更多框架来丰富网站，通过后续学习其他SpringBoot整合框架，我们就可以在我们自己的Web服务器上实现更多高级的功能，同时也我们后续学习前后端分离做准备。

## 邮件发送模块

我们在注册很多网站时，都会遇到邮箱或者手机号验证，也就是通过邮箱和手机短信来接收网站发送的注册验证信息，填写验证码后，就可以完成注册了，同时，网站也会绑定你的手机号或者邮箱。

那么像这样的功能该如何实现呢？SpringBoot为我们提供了封装好的邮件模块使用：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-mail</artifactId>
</dependency>
```

在学习邮件发送之前，我们先了解一下什么是电子邮件。

> 电子邮件也是一种通信方式，是互联网应用最广的服务。通过网络的电子邮件系统，用户可以以非常低廉的价格（不管发送到哪里，都只需负担网费，实际上就是把信息发送到对方服务器而已）、非常快速的方式，与世界上任何一个地方的电子邮箱用户联系。

要在Internet上提供电子邮件功能，必须要有专门的电子邮箱服务器。例如现在Internet很多提供邮箱服务的厂商：163，qq等等，他们都有自己的邮箱服务器。这些服务器类似于现在的邮局，它主要负责接收用户投递来的邮件，并把邮件送到接收者的邮箱中。

所有用户都可以在电子邮件服务器上申请一个账号用于邮件的发送和接收，那么邮件是以什么样的格式发送的呢？实际上，与HTTP一样，邮件也有自己的协议，也就是约定邮件数据长啥样以及如何通信。

![image-20230716172901937](https://oss.itbaima.cn/internal/markdown/2023/07/16/sL56YdmgGblfFjo.png)

比较常用的协议有两种：

1. SMTP协议（主要用于发送邮件Simple Mail Transfer Protocol）
2. POP3协议（主要用于接收邮件Post Office Protocol 3）

整个发送接收流程大致如下：

![img](https://oss.itbaima.cn/internal/markdown/2023/07/16/sOyWQguFonJKXNw.jpg)

实际上每个邮箱服务器都有一个smtp发送服务器和pop3接收服务器，比如需要从QQ邮箱发送邮件到163邮箱，那么我们只需要通过QQ邮箱客户端告知QQ邮箱的smyp发送服务器我们需要发送邮件，以及邮件的相关信息，那么QQ邮箱的smtp服务器会将邮件发送到163邮箱的pop3服务器，最后163服务器会通知用户收到了一封新邮件。

SpringBoot已经帮助我们将基本的底层通信全部实现了，我们只需要关心smtp服务器的地址以及我们要发送的邮件长啥样即可。

这里以163邮箱的https://mail.163.com为例，我们需要在配置文件中告诉SpringBootMail我们的smtp服务器的地址以及你的邮箱账号和密码，首先我们需要去设置中开启smtp/pop3服务才可以，开启后会生成一个密钥，这个就是我们的密码（而不是自己设定的登录密码）。

```yaml
spring:
mail:
    # 163邮箱的地址为smtp.163.com，直接填写即可
    host: smtp.163.com
    # 你申请的163邮箱
    username: javastudy111@163.com
    # 注意密码是在开启smtp/pop3时自动生成的，记得保存一下，不然就找不到了
    password: AZJTOAWZESLMHTNI
```

配置完成后，我们来进行测试：

## 接口规则校验

通常在使用SpringMVC框架编写接口时，很有可能用户发送的数据存在一些问题，比如下面这个接口：

```java
@ResponseBody
@PostMapping("/submit")
public String submit(String username,String password){
    System.out.println(username.substring(3));
    System.out.println(password.substring(2, 10));
    return "请求成功!";
}
```

这个接口中，我们需要将用户名和密码分割打印，在正常情况下，用户名长度规定不小于5，如果用户发送的数据是没有问题的，那么就可以正常执行，但是如果不是按照规定的，那么会直接报错。

这个时候，我们就需要在请求进来之前进行校验了，最简单的办法就是判断一下：

```java
@ResponseBody
@PostMapping("/submit")
public String submit(String username,
                     String password){
    if(username.length() > 3 && password.length() > 10) {
        System.out.println(username.substring(3));
        System.out.println(password.substring(2, 10));
        return "请求成功!";
    } else {
        return "请求失败";
    }
}
```

虽然这样就能直接解决问题，但是如果我们的每一个接口都需要这样去进行配置，那么是不是太麻烦了一点？SpringBoot为我们提供了很方便的接口校验框架：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

现在，我们可以直接使用注解完成全部接口的校验：

```java
@Slf4j
@Validated  //首先在Controller上开启接口校验
@Controller
public class TestController {

    ...

    @ResponseBody
    @PostMapping("/submit")
        public String submit(@Length(min=3)String username,
                             @Length(max=10)String password){
        System.out.println(username.substring(3));
        System.out.println(password.substring(2, 10));
        return "请求成功!";        
    }
}
```

现在，我们的接口校验就可以快速配置了：

不过这样依然会抛出一个异常，对用户不太友好，我们可以稍微处理一下，这里我们可以直接使用之前在SSM阶段中学习的异常处理Controller来自行处理这类异常：

```java
@ControllerAdvice
public class ValidationController {

    @ResponseBody
    @ExceptionHandler(ConstraintViolationException.class)
    public String error(ValidationException e){
        return e.getMessage();   //出现异常直接返回消息
    }
}
```

除了@Length之外，我们也可以使用其他的接口来实现各种数据校验：

虽然如此，但是遇到对象的时候，又不方便了，比如：

```java
@Data
public class Account {
    String username;
    String password;
}
```

```java
@ResponseBody
@PostMapping("/submit")
public String submit(Account account){   //直接使用对象接收
    System.out.println(account.getUsername().substring(3));
    System.out.println(account.getPassword().substring(2, 10));
    return "请求成功!";
}
```

此时，接口是以对象的形式接收前端发送的表单数据的，这个时候就没法像上面一样编写对用的校验规则了，那么该怎么办？

我们可以这样校验：

```java
@ResponseBody
@PostMapping("/submit")
public String submit(@Valid Account account){   //在参数上添加注解表示在这里校验
    System.out.println(account.getUsername().substring(3));
    System.out.println(account.getPassword().substring(2, 10));
    return "请求成功!";
}
```

然后我们在实体类上添加细节：

```java
@Data
public class Account {
    @Length(min = 3)   //只需要在对应的字段上添加校验的注解即可
    String username;
    @Length(max = 10)
    String password;
}
```

这样当受到请求时，就会对对象中的字段进行校验了，这里我们稍微修改一下ValidationController的错误处理，对于实体类接收参数的验证，会抛出MethodArgumentNotValidException异常，这里也进行一下处理：

```java
@ResponseBody
@ExceptionHandler({ConstraintViolationException.class, MethodArgumentNotValidException.class})
public String error(Exception e){
    if(e instanceof ConstraintViolationException exception) {
        return exception.getMessage();
    } else if(e instanceof MethodArgumentNotValidException exception){
        if (exception.getFieldError() == null) return "未知错误";
        return exception.getFieldError().getDefaultMessage();
    }
    return "未知错误";
}
```

这样就可以正确返回对应的错误信息了。

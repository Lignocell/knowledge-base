## 模块一：HTTP 与网络请求（和你的 Controller 息息相关）
### Q1：GET 和 POST 请求有什么区别？⭐⭐⭐⭐⭐（结合你写的Controller 讲！）
- GET（获取）请求通常将参数拼接到URL后面，安全性不高，常被用于搜索功能。- POST（提交）请求将（大量）数据传入请求体，由请求体发送给后端，不会暴露，通常用于账号登录等功能。
### Q2：HTTP 有哪些常见的状态码？（重点是200, 301/302, 403, 404, 500）⭐⭐⭐⭐
- 1xx：请求接收成功，需要进一步处理。- 2xx：请求接收成功，已经处理。00 OK表示处理成功。- 3xx：重定向需要客户端进一步处理，301 Moved Permently表示永久重定向，302 Found表示暂时重定向。- 4xx：客户端发送错误，403 Forbidden表示服务器理解但拒绝执行，04Not Found表示资源不存在。- 5xx：服务器错误，00 Interal Server Error表示通用服务器错误。
### Q3：HTTP 默认是长连接还是短连接？（什么是 Keep-Alive？）

- HTTP/1.0：短链接，频繁建立TCP连接，消耗大量性能；Keep-Alive表示在请求层将短连接更改为长连接。- HTTP/1.1：长连接，一个TCP能处理多个HTTP请求，但只能单行；浏览器默认。- HTTP/2.0：长连接，优化了并行机制。- HTTP/3.0：抛弃TCP协议，基于UDP的QUIC协议，从传输层避免了TCP的连接管理问题。
### Q4：HTTP 和 HTTPS 有什么区别？⭐⭐⭐⭐

- HTTP采用明文传输，任何一个中间节点都能截取内容；80端口

- HTTPS在HTTP的基础上增加了SSL/TLS加密，建立连接时需要增加额外的握手过程，43端口；防止数据被窃听篡改。
#### Q4.1：什么是对称加密和非对称加密：
- 对称加密：公钥。- 非对称加密：私钥，速度过慢，算太复杂。- HTTPS用法，建立连接时（握手阶段），==*非对称加密*==来安全地交换一把“对称密钥”。后续传输大量数据时，用这把**对称密钥**进行极速加密通信：

## 模块二：状态保持（前端和后端的“暗号”）

### Q5：HTTP 是无状态的吗？

- HTTP本质上是无状态的。- 但是在现实生活中，我们需要保持用户的登录状态，因此开发了Cookie，客户端登录时，服务器会自动发送给客户端一个Cookie，此后的每次操作，服务器都会根据Cookie识别权限。
### Q6：Cookie、Session、Token 有什么区别？⭐⭐⭐⭐⭐（极其高频！结合你项目的登录状态讲！）

- Cookie存储在客户端，在客户端之间流通，因此安全性较低；用来记忆用户偏好等轻量级数据。- Session存储在服务器端，只生成SessionID，交由Cookie进行传输，安全性较高；用来保存用户登录状态。- Token：由服务器生成一段乱码，登录时服务器将敏感信息和 Token 一块保存，登录验证时使用相同的 Token 进行验证。- JWT令牌：服务端将非敏感信息根据加密算法生成对应 Token（JWT），将Token发送到前端，前端把它存入 LocalStorage 里。每次请求带在请求头的`Authorization` 里，不管哪个服务器拿到Token，解密后都可以拿到用户的身份状态。
### Q7：禁用 Cookie 时，如何实现 Session 功能：
- URL重写：将SessionID嵌入URL中，注意安全性，使用HTTPS进行保护。- 隐藏表单字段：将SessionID存入表单中，不过只能通过POST提交。- 存储在HTTP头部：现代Web跟倾向于采用JWT令牌，通过Token进行无状态认证。

## 模块三：TCP 与底层传输（背会这5 道，计网横着走）

### Q8：TCP 和 UDP 的主要区别是什么？（应用场景各是什么？）⭐⭐⭐⭐⭐

- TCP：保证数据的完整性，数据丢失时会补发完整的数据包，因此开销会增大；适用于看重信息完整性的场景，发送邮件等等。- UDP：保证数据的传输速率，没有多次验证的计算，属于轻量级协议；适用于对实时性要求更高的场景，比如直播等。
### Q9：请解释 TCP 建立连接的三次握手过程。（大白话：为什么要三次？）⭐⭐⭐⭐⭐
1. 客户端向服务端发送SYN包作为开始准备，SYN包中存在一个初始编号。2. 服务端接收到SYN包后，发送SYN+ACK包作为回应（SYN包作为对第一握手接收到的回应）。3. 客户端接收后，再次方式ACK包作为回应，此时二者建立连接。
### Q10：请解释 TCP 断开连接的四次挥手过程。（大白话：为什么要四次？）⭐⭐⭐⭐

1. 客户端发送一个FIN字段表示接收完成，需要关闭连接。2. 服务端接收后会发送一个ACK字段，表示已经接收到信息，但是可能信息还没传输完。3. 数据传输完成后，服务端再次发送FIN字段表示准备完成，确认关闭。4. 客户端接收到FIN后，发送ACK字段，服务端接收后直接关闭。5. 客户端进入`TIME_WAIT` 状态，等待2MSL时间后才真正关闭连接，目的是确保服务器能够收到ACK报文。
### Q11：什么是 TIME_WAIT 状态？有何作用？（四次挥手中最爱问的坑）
- TIME_WAIT表示TCP断开连接后的四次挥手==主动关闭==的状态，通常需要等待2MSL，~4min）。- 防止数据包混乱，确保关闭连接的可靠性。
### Q12：TCP 如何保证数据的可靠性？（只背4 个名词：确认重传、滑动窗口、流量控制、拥塞控制）

- 确认重传：发送方会给数据的每一个字节进行编号，接收方收到后发送ACK来确认收到的数据，若未收到，则触发重传。- 滑动窗口：发送方利用**窗口**，实现==*批量发送*==，无需等待每个数据包的 ACK，极大提升传输效率。- 流量控制：接收方会操纵一个窗口，通过该窗口来确认接受到的最大数据量。通过ACK发送给发送方己方容量剩余。- 拥塞控制：发送方会根据网络状态来调整发送速率

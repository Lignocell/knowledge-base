# 基础

## 模块一：面向对象与核心语法

### Q1：面向对象三大特征是什么？

- 封装，继承，多态。- 多态：一个接口，多种实现（子类重写父类代码），提高了代码的拓展性，但是拒绝对代码进行修改。
### Q2：重载（Overload）和重写（Override）的区别：
- 重载是指定义多种相同方法名，不同参数，与返回值无关。- 重写指子类对父类方法的重写。
### Q3：接口和抽象类有什么共同点和区别？（什么时候用哪个？）

- 共同点：二者都不能直接被实例化。- 不同点：接口是用来对方法进行行为规范，可以多实现；而抽象类则是提高对代码的复用，只能单继承。
### Q4：基本类型和包装类型的区别？什么是自动装箱与拆箱？缓存池陷阱？

- 基本类型用于表示值本身，包装类型是封装了基本类型的对象，用于参与集合、泛型等场景、- 自动装箱是自动将基本类型转化成包装类型，拆箱反之，用来简化二者转化的代码。- **缓存池陷阱：** `Integer` 有缓存池，-128 到 127），在这个范围内的自动装箱，用`==`比较是相等的，超出就不等了。
### Q5：Java 中是值传递还是引用传递？

- 值传递。- 对于基本类型的传递是值本身的副本，而引用类型传递的是值所在地址的副本。

## 模块二：对象的灵魂
### Q6：对象的相等和引用相等的区别？（也就是 `==` 和 `equals` 的区别）⭐⭐⭐⭐⭐
- 对象的相等关注的是数据本身是否相等。（equals）- 引用相等关注的是二者指向的地址是否为同一地址。（==）
### Q7：`String#equals()` 和 `Object#equals()` 有何区别：
- `Object#equals()` 比较的是对象的地址
- `String#equals()`对方法进行了重写，表示对字符串进行比较。
### Q8：为什么重写`equals()` 时必须重写`hashCode()`？⭐⭐⭐⭐⭐（极其高频！说不清直接挂）
- 如果不对hashCode进行重写，则会导致逻辑相同的对象哈希编码不同，哈希存储后会造成因哈希码不同取不出来。
### Q9：什么是引用拷贝、深拷贝、浅拷贝？它们的区别了解吗？

- 引用拷贝只拷贝对象所在地址，修改后会影响原体和复制体的数据。
	```java
	Person p2=p1;
	```

- 浅拷贝只拷贝对象本身与基本类型，修改引用地址同样会影响二者。
	```java
	Person p2=p1.clone();
	```

- 深拷贝则拷贝对象的所有属性，放到另一个地址里，二者互不影响。
	```java
	String json=JSON.toJSONString(p1);
	Person p2=JSON.parseObject(json,Person.class);
	```

## 模块三：String 家族（面试官极其爱问）
### Q10：`String` 为什么是不可变的：
- 保证安全性：既保证了数据存储安全（数据在传递时被恶意篡改），又防止多线程访问时String改变后造成系统安全。- 实现字符串常量池：使得JVM实现了字符串常量池，保证了存储的利用率。- 优化哈希性能：防止哈希存储过程中，因String改变造成哈希码的错误。
### Q11：`String`、`StringBuffer`、`StringBuilder` 有何区别？⭐⭐⭐⭐⭐（必考！）
- String是不可变的，每一次拼接都是重新new了一个新的String对象。（适用于少量拼接场景）
- StringBuffer是可变的，但是由于存在锁，在多线程中安全性高于StingBuilder。（适合多线程）
- StringBuilder是可变的，不存在锁结构，在单线程中传输速度优于StringBuffer。（适合单线程）

### Q12：字符串拼接使用 `+` 还是 `StringBuilder` 更好：
- +：小范围，在编译期用于字符串常量的拼接。- StringBuilder：大范围，适用于循环中或者运行时。
### Q13：字符串常量池的作用了解吗？

- JVM创建的专门用于管理字符串常量的内存区域，避免重复创建，提高内存利用率。
### Q14：`String s1 = new String("abc");` 创建了几个对象？（经典八股，背熟答案即可）
- 若字符串常量池中存在abc：则只有一个（new的那个对象）。- 若不存在：则有两个。

## 模块四：异常机制

### Q15：`Error` 和 `Exception` 的区别？

- Error表示在JVM中无法处理的系统级错误，比如栈溢出、内存溢出等、- Exception则表示在运行中可以被程序捕获并处理的异常，比如空指针异常、数组越界等。
### Q16：`throw` 和 `throws` 的区别？

- throw后面跟语句，表示具体抛出的异常，用于触发异常流程。- throws跟在方法后，用于声明可能抛出的异常类型。
### Q17：`final`、`finally`、`finalize` 的区别？（经典文字游戏）

- final是修饰符，用来修饰方法、类、变量、- finally用于try/catch，无论异常是否出现都会被执行。- finalize是Object的方法，用于对象销毁前的清理（由JVM自动调用，不适合开发者主动）。
### Q18：`try-catch-finally` 中，如果 `catch` 中 `return` 了，`finally` 还会执行吗？

- 会，finally的执行具有强制性。- **如果在 `finally` 里面写了 `return` 语句，它会覆盖掉 `catch` 里的 `return` 值！**

## 模块五：高级特性与底层机制

### Q19：什么是反射？反射的应用场景？⭐⭐⭐⭐（结合 Spring/JDBC 讲） 

- 反射是指在程序中可以访问、修改和检查自身状态的能力。提高了代码的灵活性，但也会造成性能开销，提高了耦合度。- Mybatis通过反射将数据库查询结果映射为java对象。- 通过反射，序列化和反序列化的目标得以实现。- Ioc容器通过反射机制完成对对象的动态创建和依赖注入。- 框架通过反射机制来扫描注解，根据注解类型实现对应机制。- AOP通过反射获取方法数据并生成代理类来拓展方法功能。
### Q20：什么是泛型？有什么作用？（什么是泛型擦除？）

- 指的是一种参数化类型的机制，能够在定义方法、接口、类时使用参数类型，在实现时再指定具体类型。- 提高代码安全性，降低类型转换时发生的错误，消除显示转换，增强代码复用性。- 类型擦除：反编译后String等类会被全部消除，为了兼容以前的老代码。
### Q21：什么是注解？注解的解析方法有哪几种？注解的作用：
- 是一种元数据机制，用于为代码添加结构化标记信息，不会改变代码本身逻辑。- 编译时解析和运行时解析。- Spring 在运行时，会拿着**反射（照妖镜）去扫描所有的类。当它看到这个方法头上贴上`@Transactional` 这张便利贴时，Spring 就会掏出动态代理（找黄牛）**，在内存里偷偷给你生成一个带有事务控制逻辑的子类去代替你运行。	所以，改变逻辑的不是注解，而是**读取了注解的底层框架机制（反射+动态代理））*

### Q22：聊聊动态代理的几种方式？⭐⭐⭐⭐（Spring AOP 的底层原理）

- 动态代理指的是运行时动态生成代理类的技术。- JDK动态代理：目标类必须实现一个接口，然后Spring会优先使用。- CGLIB动态代理：通过生成子类来代理。（Boot 里默认全 CGLIB）

## 模块六：JVM ɨä

### Q23：JVM、JDK、JRE 三者的区别是什么？

- JVM是java程序运行的地方。- JDK是java开发的工具包，包含JRE，开发工具- JRE包含JVM、核心类库和运行支持文件。
### Q24：什么是字节码？采用字节码的好处是什么？

- 字节码就是编译后生成.class文件。- 字节码不依靠运行环境和硬件，所以能够在不同环境运行。- 字节码比源代码更加紧凑，所以执行效率更高。- JVM可以对字节码进行安全验证，因此安全性更高。
### Q25：为什么说 Java 语言编译与解释并存？

- **第一步（编译）：** javac将java编译成.class`字节码。- **第二步（解释）：** 程序刚跑起来时，JVM 会一行行**解释**执行字节码。- **第三步（再编译 JIT）：** 如果 JVM 发现某段代码被疯狂调用（热点代码），为了提速，`JIT（即时编译器）` 会把它直接*编译**成底层机器码缓存起来（速度飙升）。- **总结，* Java = 前期编译 + 运行期解释 + 运行期热点编译（JIT）Just-in-Time)。

## Java 虚拟机（JVM）（防身与性能调优底座）
### Q 1：请详细介绍 JVM 内存结构的整体布局？各个区域的作用？⭐⭐⭐⭐⭐

- 线程共享，	- 堆：最大区域，存储所有的对象实例和数组，采用分代设计。		- 年轻代（Eden+2个Survivor 区）：存放新对象。		- 老年代：存储长期存活对象。		- 通过分代 GC 提升回收概率，Minor GC 经常清空年轻代，而 Full GC 在老年代满了（ OutOfMemoryError (OOM) : Java heap space ）后会清空老年代。	- 方法区（元空间）：存储类元数据、常量池、静态常量、JDK 8 后使用本地内存解决永久代内存受限问题。- 私有区域：每个线程都有，且线程之间相互独立。	- 虚拟机栈：方法调用对应栈帧入栈，返回出栈，栈深超限会产生 StackOverflowError。	- 本地方法栈：native 方法服务。（Java 无法直接调用电脑硬件，通过该标签调用 C++代码）	- 程序计数器：记录当前字节码指令地址，确保线程切换后正确恢复执行，是唯一非 OOM 区域（不占内存）。- 直接内存：非 JVM 规范定义，用于 NIO 操作（将文件从硬盘中放到直接内存中，不需要去复制拷贝，可以直接读），堆外分配避免堆与 Native 堆数据拷贝，提升 IO 性能，但需手动管理（需要手动清理内存），可能会因内存耗尽触发 OOM。
### Q 2：内存溢出(OOM) 和内存泄漏 (Memory Leak) 的区别？⭐⭐⭐⭐⭐
- 内存溢出：JVM 在分配内存时，瞬时内存超过了可用内存上限，因此新创建的对象抛出OOM。- 内存泄露：程序中不再使用的内存无法被 GC 清理，导致内存持续增长。	- 比如之前的 ThreaLocal：因 Key 值被清理无法访问的 value 造成内存被占用。	- 静态集合持有大量对象引用。	- 监听器注册后未注销。	- 数据库连接未关闭。### Q 3：JVM 垃圾回收算法有哪些？各自的优缺点？⭐⭐⭐⭐
- 标记-清除：标记需要回收的对象，再统一清除。	- 优点：实现简单。	- 缺点：产生大量内存碎片，影响大对象的分配，且需要暂停程序。- 复制算法：将内存分为两块，垃圾回收时将存活对象复制到另一块区域。	- 优点：避免内存碎片，回收效率高。	- 缺点：内存利用率只有 50%。（适合新生代）
- 标记-整理：在标记后，将存活对象向内存的一端移动，清理界限外的内存。	- 优点：避免内存碎片，且不浪费内存空间。	- 缺点：移动对象的成本较高。（适合老年代）
- 分代收集算法：（主流）根据对象存活周期将堆内存划分为新生代和老年代，新生代才有复制算法，老年代采用标记-清除或标记-整理算法。
### Q 4：JVM 堆内存的分代设计是怎样的？什么是新生代和老年代？⭐⭐⭐⭐

- 新生代：存放新创建的对象，内部被划分为 Eden 区和 Survivor 区。	- 首先在 Eden 区里进行分配，当 Eden 区满时触发 Minor GC，存活对象移动到 Survivor 区；每次 GC 后，存活对象的年龄计数器加1，当对象年龄达到阈值或 Survivor 区不足时，对象晋升为老年代。	- 特点是对象死亡率较高，GC 频繁但速度快，通常采用复制算法进行垃圾回收。- 老年代：存放长时间存活的对象和大对象。	- 空间大但 GC 频率低，使用标记-清除算法或者标记-整理算法。	- 当老年代空间不足时触发 Major GC，这个过程耗时较长，会停止程序运行，但能回收大量空间。	- _【微调建议】_：面试时你可以顺口加一句黑话：“老年代空间不足触发的全局暂停，也就是著名的**STW（Stop The World）**。所以我们在调优时，核心目的就是**尽量减少 Full GC 的发生次数**。”
### Q 5：JVM 垃圾收集器、Minor GC、Major GC、Full GC 的区别？执行时机？⭐⭐⭐

- Minor GC：具体作用见上面，这里不重复了；特点是执行频率高但耗时短，对应用影响较小。- Major GC：上面也写了；特点是执行时间长，会造成较明显的应用暂停。- Full GC：最全面的垃圾回收，同时清理新生代、老年代和方法区；触发场景包括老年代空间不足、方法区空间不足等等；最耗时，会导致应用完全暂停。### Q 6：强引用、软引用、弱引用、虚引用的区别？⭐⭐⭐（重点：ThreadLocal 内存泄漏结合）
- 四种引用类型是为了配合垃圾回收机制，决定了对象的生命周期。- 强引用：只要该引用存在，那么对象就不会被回收。（内存泄露的主要原因）
- 软引用：只有当内存紧张时，会允许 GC 去回收该对象，适用于图片缓存等场景。- 弱引用：GC 一旦运行，就会回收，ThreadLocal 就是典型应用。- 虚引用：最特殊的，无法通过引用来获取对象实例，其唯一目的是配合引用队列，在对象被垃圾回收的瞬间接收通知，主要用于 NIO 的直接内存（DirectByteBuffer）的释放跟踪机制。
### Q 7：JVM 如何判断 Java 对象是否存活？⭐⭐⭐

- 引用计数法：
	- 给每个对象维护一个引用计数器，当有对象被引用时，计数器加一，引用失效时减一，当计数器为 0 时，表示可回收。	- 缺点：当出现循环引用（A 指向 B，B 指向 A），两者无法被外部访问，则计数器永远不等于 0，造成内存泄露。- 可达性分析 GC Roots：（JVM 主流）	- 从 GC Roots 出发，通过引用链向下搜索，能够到达的对象标记为存活，无法到达的标记为可回收。
### Q 8：JVM 双亲委派模型的工作原理？设计目的和优势？⭐⭐⭐（保护核心类库）
- 该模型一共有三层，从上往下依次是启动类加载器、扩展类加载器和应用程序类加载器，当我们启动程序时，系统会从下往上寻找最顶层的父类，从父类开始加载。- 目的：保证 Java 核心类库的安全性和一致性，防止恶意替换系统核心类。- 优势：避免类重复加载，维护 Java 运行环境的稳定性。
### Q 9：Java 类加载机制的整体流程是什么？⭐⭐

- 加载——验证——准备——解析——初始化
- 加载：读取 class 文件，生成类对象。- 验证：文件格式验证，字节码验证。- 准备：分配静态变量内存，设置默认值。- 解析：符号引用转为直接引用，定位内存地址。- 初始化：执行 `<clinit>()` 方法。### Q 10：JDK 1.7 和 JDK 1.8 在内存区域方面有什么核心区别？⭐⭐

- 永久代被移出，改为方法区，.8 之前在堆区定义了一个永久代，该区域的职能是现在方法区的职能，容量有限（通常为64 M-82 M），1.8 后放入物理内存，依靠电脑本身的内存（16 G）2 G）。- 内存溢出表现差异：永久代溢出 OOM，而元空间则为 Metaspace 异常。- 底层机制：永久代与堆共享 GC 机制，Full GC 时回收；元空间独立调用系统 malloc 分配内存，类卸载更为灵活，但同样会造成内存泄露 OOM，阈值更为灵活。

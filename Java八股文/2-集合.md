# 🚀 Java 集合框架

## 模块一：集合宏观认知（送分题）

### Q1：常用的集合分类以及它们的区别？

- Collection，	- List：强调有序可重复，通过索引访问。	- Set：强调无序不可重复，通过HashMap，Equals等进行比较去重。	- Queue：默认先进先出。
- Map：存在键值对，且key唯一。	- HashMap：无序。	- LinkedHashMap：保持插入访问顺序。	- TreeMap：按键排序，键重复将覆盖值。
### Q2：集合遍历的方法有哪些？

- for循环：适用于List，通常用于ArrayList遍历。- foreach（增强for循环）：适用于Collaction和Map，底层基于迭代器。- Lambda：代码简洁。- Iterator：迭代器，适用于Collaction，支持增删改查。- ListIterator：专为List创造，提供更加灵活的遍历和修改操作。- parallelStream（并行流）：适用于大数据量，不保证遍历顺序，同时修改线程会有线程安全问题。
#### Q2.1：什么是 fail-fast 和 fail-safe：
- fail-fast：适用于ArrayList，HashMap；当迭代过程中数据发生修改时，立刻抛出ConcurrentModificationException，终止迭代。- fail-safe：适用于CopyOnWriteArrayList；在迭代之前将数据进行复制，对复制品进行迭代，就算源数据发生修改不会影响迭代，但损失了时效性。
### Q3：为什么集合框架中的接口都继承自 Iterable 接口：
- 为了提高遍历的规范性，防止旧版本和新版本的循环造成冲突，因此统一实现一个Iterator()方法。

## 模块二：List 家族（面试预热）

### Q4：讲一下 Java 里面 List 的几种实现类：
- ArrayList：适合多读少写的单线程场景。（基于动态数组）
- LinkedList：适合少读多写的单线程场景。（基于双向链表）- ~~Vector：性能较低，被ArrayList取代，少用。~~
- CopyOnWriteArrayList：适合多读少写的并发场景。
### Q5：ArrayList 和 LinkedList、Vector 有什么区别？⭐⭐⭐⭐⭐（高频必考）

- ArrayList与Vector都基于动态数组，随机访问效率较高。- Vector虽然线程安全，但是性能占比较高，已被弃用。- LinkedList基于双向链表，因此增删效率较高，访问效率低。
### Q6：展开讲讲 ArrayList？（默认容量、扩容机制、底层结构）⭐⭐⭐⭐⭐
- 它底层就是一个数组，默认容量10个，但是一旦存满，他就会*自动动态扩容1.5倍*。- 只要知道索引，就可以按照索引进行查询。- 但是一旦往里面插入元素，那么就需要重新将后面的内容复制粘贴，因此适用于多读少写的场景。- 底层调用`Arrays.copyOf()` 方法，最终会调到 C++ 写的本地方法 `System.arraycopy()`，在内存层面直接进行极速的数组块拷贝。

## 模块三：Map 家族之王（HashMap 夺命连环问）👑👑👑

*（注：这是整个 Java 面试中含金量最高的模块，没有之一！必须彻底搞懂！）

### Q7：聊聊你对 HashMap 的理解？（底层数据结构：1.7 和 1.8 的区别）⭐⭐⭐⭐⭐
- 1.7：底层由数组和链表进行实现，但是数据太多时查询效率变慢。O(n)
- 1.8：如果数据超过8（如果数据降低至6，则退化成链表），那么改由红黑树来进行存储，提高查询效率。O（log n）
### Q8：HashMap 是怎么解决哈希冲突问题的？

- 链表法：将两个存在冲突的值存放在同一个哈希桶中并用链表（红黑树）连接。
### Q9：Java 8 对 HashMap 做了哪些优化：
- 引入红黑树：当发生恶意哈希攻击（无限插入同一哈希格，形成无限链表）时，降低造成影响。- 将头插法改为尾插法：头插法扩容运行时，会造成链表反转，出现死循环。- 阈值为什么是8：通过泊松分布的计算（在正常的哈希算法下，一个格子里能塞满 8 个元素的概率只有0.00000006）。并且红黑树占用存储空间是链表的两倍。
### Q10：HashMap 是怎么扩容的？⭐⭐⭐⭐⭐
- 当负载因子增长到0.75时（容量占据75%时）开始扩容。- 重新创建一个数组，并将容量扩大到原来的2倍。- 将原数据重新进行**哈希计算**，存放到新位置。

## 模块四：Set 家族和 Map 的衍生（扩展防身）
### Q11：聊聊你对 HashSet 的理解？

- HashSet本质上HashMap的封装；key存储的是HashMap的key值，value存储的是一个假对象（PRESENT）。- 不保证插入顺序，但key值保证不重复。- 通过数据的hashCode()确定存储位置，通过equals()比较去重。- 需要维护插入顺序则选择LinkedHashSet，需要维护排序则选择TreeSet。
### Q12：什么是 LinkedHashMap？其实现原理是什么？（如何保证插入顺序？）
- LinekedHashMap是HashMap的子类；
- 既通过底层数组保留了查询效率，又使用双向链表来维护插入顺序。
### Q13：聊聊 Java 中的 TreeSet， TreeMap 是什么？

- TreeSet底层是TreeMap实现的，核心数据结构依然是红黑树，能保证其存储的有序性。- TreeSet的元素均被存入TreeMap的key中，value为固定静态常量。

## 模块五：并发集合基础（JUC 敲门砖，点到为止）
*（注：日常实习极少深挖，只要能说出名字和基本原理即可）

### Q14：HashMap 是线程安全的吗？和 HashTable 有什么区别？

- 不是。- HashMap的key和value均可定义null值，效率更高，底层基于拉链法＋红黑树，初始容量为16，扩容1倍。- HashTable的key和value不可定义null，因锁机制导致效率低，底层基于拉链法，初始容量为11，扩容为原容量的2倍加1。
### Q15：如何将一个线程不安全的集合转为线程安全的？（Collections 工具类）

- 低并发（日常使用）：使用Collections进行包装类。- 高并发：使用JUC包里的并发集合，如ConcurrentHashMap、CopyOnWriteArrayList。
### Q16：Java 中的 ConcurrentHashMap 是什么？和 HashMap 有什么区别？⭐⭐⭐⭐（高频）

- ConcurrentHashMap是由java提供的线程安全的Map，java8之前使用分段锁，java8之后则使用synchronized+CAS实现。- HashMap可以让key和value定义为null，线程不安全，多线程下会抛出异常，效率更高，适合单线程模式下。- ConcurrentHashMap反之。
### Q17：ConcurrentHashMap 在 JDK 1.7 和 JDK 1.8 中的实现原理？主要改进？（分段锁 vs CAS+synchronized）⭐⭐⭐⭐

	底层结构与 1.8 HashMap 保持一致（数组+链表+红黑树）。

# Java 并发编程（JUC）

### Q 1：什么是线程池？使用线程池的优势？ThreadPoolExecutor 的核心参数有哪些？⭐⭐⭐⭐⭐

- 线程池是 JUC 提供的一种线程管理机制，通过复用固定数量的线程来执行任务，避免频繁创建销毁线程造成额外开销。- 优势，  - 降低系统资源损耗。  - 提高响应速度。  - 控制并发数量。- 核心参数，  - corePoolSize：核心线程数量。  - maximumPoolSize：最大线程数上限。  - keepAliveTime：非核心线程空闲期存活时间。  - workQueue：核心线程占用时，其他任务会进入队列等待。  - threadFactory：创建新线程的工厂。  - rejectedExceptionHandler：队列存满时的拒绝策略。
### Q 2：线程池的执行流程是怎样的？当核心线程数已满时提交任务会发生什么？⭐⭐⭐⭐⭐
1. 首先，当出现任务时，核心线程会开始工作。2. 当核心线程被全部占用时，任务会进入队列中进行等待。3. 队列存满后，当线程池识别到又有任务到来，会创建其他线程，数量为最大线程数 - 核心线程数，并处理新到来的线程。4. 当线程到达上限时，根据拒绝策略来处理新来的线程。
### Q 3：线程池的拒绝策略有哪些？⭐⭐⭐⭐
- AbortPolicy：抛出异常（RejectedExecutionException）- CallerRunsPolicy：调用线程处理被抛弃的任务。（主线程）
- DiscardPolicy：静默丢弃任务（适用于对任务丢失不敏感的场景）。- DiscardOldestPolicy:丢弃最老的任务（队列中最开头的任务），转而执行新的任务（队列中排第二的任务）。
### Q 4：synchronized、volatile、CAS 的区别与适用场景？⭐⭐⭐⭐
- synchronized：重量级锁，是悲观锁。- volatile：只用来做状态标记，保证变量的可见性。- CAS：无锁机制，它是 CPU 指令，是乐观锁，使用于冲突较少的高并发场景。
### Q 5：乐观锁和悲观锁的概念？各自的实现方式和适用场景？⭐⭐⭐⭐
- 乐观锁和悲观锁的概念在 MySQL 中讲过，自己跳转复习。- 乐观锁：适用于多读写少，版本号机制；这里拓展一下 CAS 机制，它准备修改内存时，先偷看一眼当前值，如果和预想的一样，瞬间改掉；如果发现被别人改过了，它就放弃修改，重新循环再试一次（自旋）。
### Q 6：ThreadLocal 的作用和实现原理？为什么会引发内存泄漏问题？⭐⭐⭐

- 作用：解决多线程环境下的变量共享（将变量复制到 ThreadLocalMap）问题。当多个线程访问同一个 ThreadLocal 变量时，每个线程都会获得自己的独立实例，互不干扰。- 原理：TheadLocal 定制的 HashMap，每个线程都有一个属于自己的 Map，当需要获取数据时，ThreadLocal 会提取 Key（相当于钥匙），来开启线程的 Map（其实就是线程公用一把钥匙的意思），Key 值存放的是 ThreadLocal 对象本身，就是每个线程在 Map 中拥有自己特定的值。- 内存泄露问题：当线程被回收（key 值置为 null），但是 value 依然存在数据，而且无法清理，造成问题。	  - 解决方法：在使用完后主动调用 remove() 清理。
### Q 7：创建线程有哪几种方式？Runnable 和 Callable 接口的区别？⭐⭐⭐

- 继承 Thread 类：
  - 做法：创建一个类继承 Thread，重写 run()方法，调用 start()。  - 优点：适合小型测试。  - 缺点：受限于 Java 单继承方式，无法再继承其他的类。- 实现 Runnable 接口，  - 做法：创建一个类实现 Runnable 接口，实现 run() 方法，将其实例传递给Thread 构造函数。  - 优点：避免单继承限制，多个线程可以共享一个任务对象。  - 缺点：返回值是 void，无法直接获取线程执行结果。- 实现 Callable 接口 + FutureTask
  - 做法：实现`Callable<T>` 接口，重写 call() 方法,配合 FutureTask 使用，提交给线程或者线程池。  - 优点：支持返回值和异常处理，比 Runnable 更灵活。  - 缺点：使用较复杂，需要 FutureTask 包装。- 使用线程池：
  - 做法：使用 ExecutorService 提交 Runnable 和 Callablle 任务，统一交给线程池管理。  - 优点：线程复用，性能高，适用于高并发。  - 缺点：需要配置线程池参数，可能会大致资源耗尽或任务堆积。- CompletableFuture：脱胎于线程池。  - CompletableFuture.runAsync(() -> {炒菜...}, threadPool)（异步任务编排）。

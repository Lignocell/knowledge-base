# 数据库基础

数据库是学习JavaWeb的一个前置，只有了解了数据库的操作和使用，我们才能更好地组织和管理网站产生的数据。
## 什么是数据库基础

数据库是数据管理的有效技术，是一批数据构成的有序集合，这些数据被存放在结构化的数据表中。
再JavaSE的学习当中，我们学习了如何使用文件I/O来将数据存储到本地，即使程序重新打开，我们同样能够加载上一次的数据，但是，当我们的数据变得非常非常多的时候，我们需要使用数据库来进行快速查找、便捷插入，增删改查等等一系列的功能。
## 常见的数据库

包括但不限于：
- MySQL-免费的，用的最多的，开源数据库，适用于中小型。- Mincrosoft SQL Server-收钱的，但是提供技术支持，适用于Windows Server。- Oracle-收钱的，大型数据库系统。
而我们要学习的MySQL数据，无论学习哪种数据库，SQL语句大部分都是通用的，只有少许不一样。
## 数据模型

还记得我们之前学习的类吗，其实是对现实世界数据的一种抽象，比如一个学生的姓名、年龄、学号等等，这些特征也被称为实体的一种属性，属性具有以下特点：

- 属性不可再分。- 一个实体可以有多个属性。- 用于区分不同实体的属性（学号之于学生，身份证号之于中国公民），被称为Key。- 属性取值可以有一定的约束，比如性别只能是男或女。
实体或是属性之间可以具有一定的联系，比如一个老师可以教很多个学生，而学生相对于老师就是被教授的关系；又比如每个同学都有一个学号与其唯一对应，因此学号和学生之间也有一种联系。而像一个老师教多个学生的联系就是一种一对多的联系（1:n），而学号唯一对应，就是一种一对一的联系（1:1）；每一个老师不仅可以教多个学生，每一个学生也可以有多个教师，这就是一种多对多的联系（n:m）。
MySQL就是一种关系型数据库，通过使用关系型数据库，我们就可以很好地存储这样带有一定联系的数据。

## 数据库的规范化
首先，哦我们需要学习一下如何设计一个表。
### 第一范式，NF：
第一范式指的是每一列都是不可分割的基本数据项，而下面这样的就存在可分割的情况：

- 学生的电话号码
电话号码包括家用座机电话和移动电话，即可拆分。
- 学生（座机电话，移动电话）
此时满足第一范式的基本要求。
### 第二范式，NF：
第二范式要求表中必须存在主键，且其他属性必须完全依赖于主键。比如：

- 学生，u>学号</u>，姓名，性别：
学号是学生的唯一标识，每个学生所有属性都依赖于学号，学好改变代表学生发生改变，所以此表满足第二范式。
### 第三范式，NF：
在满足第二范式的前提下，所有属性都不传递依赖于主键，满足第三范式。
- 学生借书情况，u>借阅编号</u>，学生学号，书籍编号，书籍名称，书籍作者）

实际上，书籍编号依赖于借阅编号，而书籍名称和书籍作者依赖于书籍编号，因此存在传递依赖的情况，我们可以将书籍信息进行单独拆分成另一张表。
- 学生借书情况，u>借阅编号</u>，学生学号，书籍编号，- 书籍，u>书籍编号</u>，书籍名称，书记作者）

此时满足第三范式。
### BCNF

BCNF作为第三范式的补充，假设仓库管理关系表为StorehouseManage(仓库ID，存储物品ID，管理员ID，数量)，且有一个管理员只在一个仓库工作；一个仓库可以存储多种物品，这个数据库表存在如下决定关系：
（仓库ID，存储物品ID）>（管理员ID，数量）

（管理员ID，存储物品ID）>（仓库ID，数量）

所以，表中的唯一非关键字段是`数量`。
但是，它是符合第三范式的，由于存在如下关系：

仓库ID->管理员ID

管理员ID->仓库ID

即存在关键字段决定关键字段的情况，如果修改管理员ID，那么就必须逐一进行修改，所以不符合BCNF范式。
## 使用SQL语句

结构化查询语言（Structured Query Language）简称SQL，这是一种特殊的语言，他专门用于数据库的操作，每一种数据库都支持SQL，但数据库之间都存在自己的“方言”。
SQL语句不区分大小写（关键字推荐用大写），它支持多行，每一行结束使用`;`来结尾。
SQL也支持注释，通常使用 `--`或者`#`来编写注释内容，也可以使用`/*`来进行多行注释。
我们要学习的就是以下四种类型的SQL语言：
- 数据查询语言（Data Query Language, DQL）基本结构是由SELECT子句，FROM子句，WHERE子句组成的查询块。- 数据操纵语言（Data Manipulation Language, DML）是SQL语言中，负责对数据库对象运行数据访问工作的指令集，以INSERT、UPDATE、DELETE三种指令为核心，分别代表插入、更新与删除，是开发以数据为中心的应用程序必定会使用到的指令。- 数据库定义语言DDL(Data Definition Language)，是用于描述数据库中要存储的现实世界实体的语言。- DCL（Data Control Language）是数据库控制语言。是用来设置或更改数据库用户或角色权限的语句，包括（grant,deny,revoke等）语句。在默认状态下，只有sysadmin,dbcreator,db_owner或db_securityadmin等人员才有权力执行DCL。
我们平时所说的CRUD其实就是增删改查（Create/Retrieve/Update/Delete）。

- date存储日期
- time存储时间
- year存储年份
- datetime用于混合存储日期+时间

### 修改表
如果想要修改表，如下所示：

```sql

## 数据库操纵语言（DML）
前面我们已经学习了关于库和表的相关操作，而表中的数据插入，删除以及更新，则是本版块的重点。

```sql
INSERT INTO 表名 VALUES(值1,值2,值3)
```

如果插入的数据与列名一一对应，那么可以省略列名，但是如果希望指定列上插入数据，就需要给出列名：

```sql
INSERT INTO 表名（列名1，列名2）VALUES(值1，值2)
```

我们也可以一次性向数据库中插入多条数据：
```sql
INSERT INTO 表名（列名1，列名2）VALUES(值1，值2),(值3，值4),(值5，值6)
```

### 修改数据

我们可以通过`update`来更新表中的数据：
```sql

## 数据库查询语言（DQL）
数据库查询是整个数据库学习中的重点内容，面对数据库中庞大的数据，该如何去寻找我们想要的数据。
### 单表查询

单表查询是最简单的一种查询，我们只需要在一张表中去寻找数据即可：
```sql
SELECT * FROM 表名  #查询表中所有数据SELECT 列名,列名 FROM 表名  #查询两个列下的数据SELECT DISTINCT 列名 FROM 表名  #只查询不重复的值```

我们也可以添加where来限定查询目标：

```sql
SELECT *FROM 表名 WHERE 条件
```

### 常用查询条件

- 一般的比较运算符，包括=、<>、!=、<=、>=等。- 是否在集合中：in、not in
- 字符模糊匹配：like，not like
- 多重条件连接查询：and、or、not

### 排序查询

使用order by对查询结果进行排序：

```sql
SELECT *FROM 表名 WHERE 条件 ORDER BY 列名 ASC|DESC
```

ASC表示升序排列，DESC表示降序排列，默认是升序。
我们也可以添加多个排序：

```sql
SELECT *FROM 表名 WHERE 条件 ORDER BY 列名1 ASC|DESC 列名2 ASC|DESC
```

这样我们先按照列名1进行排列，每组列名1相同的数据再按照列名2进行排序。
### 聚集函数

聚集函数一般用作统计，包括：
- `count([distinct]*)`统计所有的行数（distinct表示去重再统计，下同）- `count([distinct]列名)`统计某列的值总和
- `sum([distinct]列名)`求一列的和（注意必须是数字类型的）- `avg([distinct]列名)`求一列的平均值（注意必须是数字类型）
- `max([distinct]列名)`求一列的最大值- `min([distinct]列名)`求一列的最小值
一般聚集函数是这样使用的：

```sql
SELECT count(distinct 列名) FROM 表名 WHERE 条件 
```

### 分组和分页查询
通过使用group by来对查询结果进行分组，它需要结合聚集函数一起使用：

```sql
SELECT sum(*) FROM 表名 WHERE 条件 GROUP BY 列名
```

我们通过having来限制分组条件：

```sql
SELECT sum(*) FROM 表名 WHERE 条件 HAVING 约束条件
```

我们通过limt来限制查询的数量，只取前n个结果：

```sql
SELECT * FROM 表名 LIMIT 数量
```

我们也可以这样分页：

```SQL
SELECT *FROM 表名 LIMIT 起始位置,数量
```

### 多表查询

多表查询是同时查询两个或者两个以上的表，多表查询会通过连接转换为单表查询。
```sql
SELECT*FROM 表1, 表2
```

直接这样查询会得到两张表的笛卡尔积（也就是每一项数据和另一张表的每一个数据结合一次）会产生庞大的数据。
```sql
SELECT*FROM 表1, 表2 WHERE 条件
```

这样才可以得到满足条件的数据。
注意：当两张表中带有相同的属性，我们需要添加表名前缀来指明。
### 自身连接查询

自身连接，就是将表本身与表进行笛卡尔积计算，得到结果，但由于表名相同，因此我们需要起一个别名：

```sql
SELECT * FROM 表名 别名1,表名 别名2
```

### 外连接查询
外连接就是专门用于联合查询情景的，比如现在有一个存储所有用户的表，还有一张用户详细信息的表，我们希望将两张表结合到一起来查看完整的数据，我们就可以通过使用外连接来进行查询，外连接有三种方式：

## 视图

视图本质上就是一个查询的结果，不过我们每次都可以通过打开视图来按照我们想要的样子查看数据，既然视图本质上是一个查询结果，那么它本质上是是一个虚表，并不是真实存在的，数据实际上还是存放在原来的表中。
创建视图：
```sql
CREATE VIEW 视图名称(列名) as 约束条件[WITH CHECK OPTION];
```

WITH CHECK OPTION是指当创建后，如果更新视图中的数据，是否要满足子查询中的条件表达式，不满足将无法插入，创建后，我们就可以使用select语句来直接查询视图上的数据l，我们甚至可以在原视图的基础上导出其他视图。
1. 若视图是由两个以上基本表导出的，则此视图不允许更新。2. 若视图的字段来自字段表达式或常数，则不允许对此视图执行INSERT和UPDATE操作，但允许执行DELETE操作。3. 若视图的字段来自集函数，则此视图不允许更新。4. 若视图定义中含有GROUP BY子句，则此视图不允许更新。5. 若视图定义中含有DISTINCT短语，则此视图不允许更新。6. 若视图定义中有嵌套查询，并且内层查询的FROM子句中涉及的表也是导出该视图的基本表，则此视图不允许更新。例如将成绩在平均成绩之上的元组定义成一个视图GOOD_SC，CREATE VIEW GOOD_SC AS SELECT Sno, Cno, Grade FROM SC WHERE Grade > (SELECT AVG(Grade) FROM SC); 　　导出视图GOOD_SC的基本表是SC，内层查询中涉及的表也是SC，所以视图GOOD_SC是不允许更新的。7. 一个不允许更新的视图上定义的视图也不允许更新。
通过`drop`来删除一个视图：

```sql
drop view 视图名称
```

## 索引

当数据量十分庞大时，通过创建索引，能够大大提高我们的检索效率，就像Hash表一样，它能够快速定位元素存放的位置，我们可以通过如下命令来创建索引：

```sql
CREATE INDEX 索引 ON 表名（列名） #创建索引
SHOW INDEX FROM 表名  #查看表中的索引```

我们也可以删除索引：

```sql
drop index 索引名称 from 表名
```

虽然添加索引会使得检索效率更高，但是我们不能过度使用索引，因为索引会在数据更新世产生额外的开销，同时也会占用磁盘资源。
## 触发器
触发器和名字一样，在某种特定的条件下才会自动触发，在`select/update/delete`时，会自动执行我们预先设定的内容，触发器通常用于检查内容的安全性，相比直接添加约束，触发器显得更加灵活。
触发器锁依附的表被称为基本表，当触发器表上发生`select/update/delete`时，会自动生成两个临时的表（new表和old表，只能由触发器使用）。
比如在`insert`操作时，新的内容会被插入到new表中；在`delete`操作时，旧的内容会被移到old表中，我们仍可以在old表中拿到被删除的数据；在`update`中，旧的内容会被移动到old表，新内容会被移动到new表中。
```sql
CREATE TRIGGER 触发器名称[BEFORE|AFTER] [INSERT|UPDATE|DELETE] ON 表名 FOR EACH ROW [INSERT|UPDATE|DELETE] FROM 表名 WHERE 条件;
```

![image-20250723110028578](D:/knowledge_point/images/image-20250723110028578.png)

BEFORE和AFTER表示是在执行操作之前触发还是在执行操作之后触发。
FOR EACH ROW 表示针对每一行都生效，无论哪行进行指定操作都会执行触发器。
查看触发器：

```sql
SHOW TRIGGERS;
```

删除触发器：

```sql
DROP TRIGGER 触发器名称```

## 事务

当我们进行的操作十分多时，比如要依次删除多个表的数据，我们就需要执行大量的sql语句来完成，这些语句可以构成一个事务。只有Innodb引擎支持事务，我们可以这样来查看支持的引擎：

```sql
SHOW ENGINES;
```

mysql默认采用了innodb引擎，我们也可以去修改为其他的引擎。
事务具有以下特性：

- **原子性：** 一个事务（transaction）中的所有操作，要么全部完成，要么全部不完成，不会结束在中间某个环节。事务在执行过程中发生错误，会被回滚（Rollback）到事务开始前的状态，就像这个事务从来没有执行过一样。- **一致性：** 在事务开始之前和事务结束以后，数据库的完整性没有被破坏。这表示写入的资料必须完全符合所有的预设规则，这包含资料的精确度、串联性以及后续数据库可以自发性地完成预定的工作。- **隔离性：** 数据库允许多个并发事务同时对其数据进行读写和修改的能力，隔离性可以防止多个事务并发执行时由于交叉执行而导致数据的不一致。事务隔离分为不同级别，包括读未提交（Read uncommitted）、读提交（read committed）、可重复读（repeatable read）和串行化（Serializable）。- **持久性：** 事务处理结束后，对数据的修改就是永久的，即便系统故障也不会丢失。
```sql
begin;  #开始事务...
rollback;  #回滚事务
savepoint 点的名字;  #添加回滚点rollback to  #回滚到指定回滚点
...
commit;  #提交事务
--一旦提交，就无法再进行回滚了。```
